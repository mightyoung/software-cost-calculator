# 采购工具 UI 交互契约

状态：开发交接稿，2026-09-17。本文细化已批准范围，不表示界面或服务已实现。视觉方向为面向采购人员的本地工作工具：清楚、克制、便于核对记录，采用 Flutter 原生组件语义；属于 Impeccable 的 Operate 模式。taste-skill 明确不面向数据表与多步骤产品 UI，仅采用适用的视觉克制、双主题和可访问性原则，不采用其营销页布局、Web 组件包或动效默认值。

依据：[批准设计第3至8节](../superpowers/specs/2026-09-16-supplier-inquiry-design.md)、[执行 PRD 第3节与 T8/T10](../../.omx/plans/prd-supplier-ralplan.md)、[现有核心边界类型](../../packages/supplier_core/lib/src/contracts.dart)。当前未发现项目 PRODUCT.md / DESIGN.md；不虚构既有品牌或已验证视觉稿。

## 1. 范围、状态与接入前提

用户已延期 Windows/Android 设备验证并要求继续开发，见[执行记录](execution-2026-09-17.md)和[平台能力报告](../verification/platform-capabilities.md)。这允许开发继续，不把设备未测改为通过。

历史设备验收状态不作为正式界面或写入的运行期门。原生适配启动时实际打开持久 SQLite、取得可靠应用写锁并完成活动库指针初始化，即可进入工作界面并开放对应业务写入；内存回退、持久化不可用或跨写者锁不可用时才按运行期事实拒绝写入并解释原因。现有探针工程壳将替换为真实启动流程，不以硬编码能力 PASS 或要求设备报告先 PASS 代替初始化。

T8 提供本地录入、查找、业务 Excel、备份重开的 M1 闭环，依赖 T7 及其上游。T10 在 T8+T9 后接入完整同步预览、冲突、关联修复及任务恢复。T8 不提前宣称完整同步可用。UI 只调用公开服务，不直接修改数据库、组装可信验证令牌、生成修订历史或实现临时内存 CRUD。

本轮仅交付本文。在内核负责人冻结公开方法签名、输入/结果 DTO、失败码及任务观察契约之前，不编码业务界面。下文服务名来自批准设计；动作名是所需能力，不声称同名 Dart 方法已存在。`DomainFailure`、`CaptureMode`、`InquiryPrecision`、`RowAction`、`JobState`、`PreviewToken`、`CommitReceipt` 为现有边界类型；其余展示模型由对应服务 owner 冻结后使用。

不增加账户、登录、角色权限、业务服务器、订单库存、待回复流程、项目主表或询价单主表。首页直接进入“查询与比价”，不增设无业务价值的统计仪表盘。

## 2. 页面、服务与状态映射

| 供应商及联系人 | 查找供应商、维护公司与联系人、查看相关报价、联系动作 | QueryRepository + T4 RecordService；联系动作由平台入口处理 | 有效、已删除、重定向、关联异常、并发编辑冲突；历史联系人快照独立 |

## 3. 桌面表格与移动表单

Windows/Web 宽屏采用侧边导航、页标题/主操作、筛选区、分页表格和详情区域。表格默认每页50条，使用服务稳定游标；保留筛选、列显隐和返回位置，不为跳页、筛选或计数一次加载十万条。批量操作明确显示“本页已选 N 条”，不得把未加载行暗算为已选；跨页选择能力须等查询契约明确。

查询默认列为产品（名称、品牌型号）、供应商、精确价格及口径、项目名称/编号、询价日期、报价日期、询价人、记录状态。次要联系信息、地点和备注进入详情或可选列。金额右对齐，同行单位/币种/税制可辨；排序箭头和列名一起朗读。长名称允许换行或进入可复制完整详情，不用只在悬停时可见的文本承载关键信息。

窄屏按可用宽度改成搜索列表和整页详情，不把桌面十列挤成细字。列表优先显示产品、供应商、价格口径、报价日期及异常提示；筛选入口显示已应用条件数量，打开后可逐项清除。新报价按“供应商与产品 → 价格与联系 → 项目与日期 → 核对保存”分步展示，同一草稿返回上一步不丢字段。桌面可同页分组录入，校验规则一致。系统返回有未保存修改时提供继续编辑或放弃，不暗中提交草稿。

手机联系操作只使用用户点选的电话号码/地址调用平台能力，失败提供复制文本；不自动拨号或代发消息。键盘出现时当前字段、错误和下一步入口可达；大字号时允许表单纵向重排。

## 4. 字段、精度与标准/历史规则

| 字段组 | 输入与呈现契约 |
|---|---|
| 供应商 / 联系人 / 产品 | 使用明确身份选择与可见候选，不按相似名字自动合并；联系人必须属于所选供应商。报价联系人使用当时快照，主联系人后续修改不重写历史；允许按领域规则输入完整独立联系快照 |
| 已知价格 | 必填，零为真实零报价；十进制文本，非负，最多12位整数与6位小数。输入、校验、显示、排序、复制与导出均不经 `double` 转换；超精度拒绝且保留原输入，不静默四舍五入 |
| 数量与单位 | `min_qty` 相同12+6精度且大于0，默认1；单位快照明确显示，修改产品默认单位不改变既有报价。数量也按精确文本传输 |
| 币种与税制 | 币种三位大写，默认 CNY；含税/未税/未知，默认未知；税率可空，0至100、最多4位小数。不推算未知税制或自动换汇 |
| 项目信息 | 标准新建项目名称/编号至少一项；只存当前报价快照，不创建项目主表，不批量改历史。项目编号和电话号码始终文本，保留前导零 |
| 询价时间 | 标准新建选择“仅日期”或“具体时刻”；前者不显示伪造的00:00，后者预览当地日期、时刻和明确时区偏移。缺秒输入按分钟起点记录并在最终预览可见；非法日期/精度拒绝 |
| 报价日期 / 有效期 | 报价日期与询价日期独立，标准新建必填。有效期需存在报价日期且不早于它；历史缺失不补今天或询价日期。交期为0至36500天或空 |
| 询价人 / 地点 | 标准新建询价人必填，地点选填；字段长度和字符处理直接使用核心规则，错误定位到对应输入，不另写一套宽松校验 |

标准新建不提供“改为历史模式”来绕过必填。只有普通 Excel 的明确历史资料入口允许上下文缺失；供应商、产品及已知价格仍不可缺。历史记录以“历史资料”及实际缺失项显示，空白分别呈现“未记录/日期未知”，不用0、今天或占位联系人替代。

历史纠错保留其他未知字段；清空已有信息需明确操作。补齐后“转为标准记录”创建新修订。复制任何报价为新询价均执行 standard 校验，历史例外不继承。三类动作文案固定为“纠正原报价”“复制为新询价”“删除记录”：前者同ID新修订，复制新ID，删除保留历史；服务成功回执返回后才刷新为已保存。

## 5. 查询、比较与记录状态

组合筛选包含供应商/联系人、产品名称/品牌/型号、项目名称/编号、询价日期范围/精度/缺失、询价人、报价日期、价格范围、历史缺失状态。询价日期按保存的当地日期筛选，不随当前设备时区漂移；只有日期的记录不参与猜测日内先后。

比价分组键由服务返回：canonical 产品、单位快照、币种、税制、起订量；含税再区分税率。UI 不在已加载一页自行算全局最低价。未知税制仅展示；报价日期未知/未来、过期、实体异常及冲突记录排除“已确认有效最低价”；有效期未知标“有效期待确认”。明确列出排除原因并可切到全部历史，不隐藏不利或异常报价。

每供应商“最新报价”按报价日期，日期相同则并列显示。UUID、修订时间或仅到日的询价日期不能被用来选唯一最新。合并实体的原引用与当前归属在详情可追溯，删除不级联消失历史报价。

## 6. Excel、确认身份与任务状态

业务 Excel 流程：选标准/历史资料 → 选表及映射 → 格式转换预览 → 行校验/匹配 → 修改原记录/新增询价/跳过/显式排除错误行 → 最终汇总 → 确认。逐行显示来源行号、原值、转换值、错误与操作；错误排除数量和原因始终可复查。

更新时空白默认“保留”，清空必须明确选择；新建空白为 null。旧文件修改展示当前值、来件和可用导出基线，缺基线不声称可自动识别新旧。数值精度损坏、公式、无法还原的长编号拒绝猜测；无时区的本地日期时间要求明确批次偏移，展示1900/1904日期系统转换结果。

已确认回执命中时默认显示“已导入，跳过”，可查看原选择与结果；另一次真实询价须显式重新确认。一次确认的 `confirmation_event_id` 由服务持久登记并复用，双击、响应丢失和重开重试不能生成新事件。UI 禁用重复提交只是反馈，不能替代服务幂等；结果使用 `CommitReceipt.resultCursor` 分页，不能收集所有导入ID。

| 服务状态 | 页面反馈 | 允许动作与边界 |
|---|---|---|
| created / parsing | 等待处理 / 正在读取；阶段、已处理数量与可靠总数 | 可取消；未知总数使用不确定进度，不编百分比 |
| validating | 校验内容与关联 | 可取消；暂存未进入业务查询 |
| previewReady | 汇总新增/修改/跳过/错误/冲突与决定 | 确认或返回调整；携带原 `PreviewToken`，不自行重签 |
| 预览版本变化 | “数据已变化，请重新核对” | 回到 validating；旧决定可对照但不自动应用到新目标 |
| committing | 正在保存；请求取消时显示等待实际结果 | 由服务决定回滚还是已提交，不能显示虚假撤销 |
| committed | 完成数量与结果入口 | 重开查询持久回执；不能再次当作新询价提交 |
| cancelled / failed | 已取消 / 未完成及可操作原因 | 按持久任务安全重试；缺源文件须重选并校验同一摘要 |

技术层 `previewReady` 对应规格中的 `preview_ready`。展示的子阶段由服务提供；备份或恢复步骤不由 UI 擅自增改持久 `JobState`。解析进度或暂存批次成功不显示为业务导入成功。同步包缺卷或错误时整包拒绝，不提供排除错误卷后提交的入口；该规则与业务 Excel 可显式排除错误行分开。

## 7. 冲突、删除与关联修复（T10）

冲突详情显示全部 heads 对应的完整版本、差异、业务日期、设备来源提示及删除状态；时间只供参考，不排列“赢家”。桌面并排对照，手机逐分支切换并保留差异摘要。默认不预选胜出版本；并行内容相同也须用户确认完整版本。

用户可选择完整版本或人工编辑完整结果，选择阶段只形成决定草稿。确认后 RecordService 创建继承全部已知 heads 的后继；失败保留所有分支，预览过期重新核对，后来第三端分支仍可再次触发冲突。删除与修改冲突时必须明确保留删除或恢复内容，不隐式复活。

合并前显示保留实体、来源实体及受影响引用；一次服务事务完成目标 put 与来源 redirect。重定向环或并行重定向标“关联异常”，阻止该分量参与新录入和最低价；提供选择保留实体的显式修复。误合并通过新恢复/重定向修订修复，不提供抹除旧历史的伪撤销按钮。

## 8. 备份、文件输出与失败反馈

导入非空库前的备份与预览版本由服务绑定；备份后数据变化则重新预览/备份，UI 不凭曾显示过成功就跳过。恢复流程呈现“验证候选备份 → 核对影响 → 确认恢复 → 切换 → 重开检查”；重开完整性检查成功后才显示“恢复完成”，切换期间禁止编辑。设备身份不从备份覆盖。

导出先生成并自验临时输出，再发布。支持可靠文件句柄时由用户手势先选择目标，等待文件流 close 成功后才显示该API“写入完成”；下载回退只能显示“下载已发起”，不能写“已保存到磁盘”。取消或授权丢失、close失败、空间不足保留明确结果和重试入口，不公开半包、不自动删历史。浏览器可靠大包路径不可用时说明该能力不可用，不以整包 Blob 掩盖。

| 情况 | 文案与操作 |
|---|---|
| 首次空库 | “尚无报价”；提供新报价、导入业务 Excel；不填入演示公司或虚构价格 |
| 筛选无结果 | 展示当前条件，提供清除部分/全部条件；不伪装为空库 |
| 字段失败 | 字段下给原因，顶部简短错误汇总可跳到首个错误；保留输入，不能仅红框 |
| 写锁或平台能力不足 | 清楚显示只读及原因，读取/导出仍尽可能开放；不显示保存成功或循环重试 |
| 空间不足 | 说明本次操作未完成，提供清理应用暂存、外部备份/迁移入口；提交中失败由服务回滚 |
| 读取失败 | 保留筛选/草稿并提供重试；旧内容若保留须标注未刷新，不当作最新 |
| 文件丢失 / 授权失效 | 提供重新选择原文件/目标；源摘要不匹配不能接续同一任务 |

`DomainFailure.field` 用于定位字段，`code` 用于稳定行为映射；技术 `cause` 进入可复制本地诊断。服务尚未冻结的错误码和重试条件不得由 UI 猜测。应用退出不承诺后台继续，重开以持久任务和回执恢复事实。

## 9. 浅色、深色与可访问视觉方向

默认跟随系统，允许选择浅色/深色；同页保持一个主题。浅色用中性浅底、清晰内容面与深色文字；深色用中性深底和逐级提亮的面、浅色文字。单一克制强调色用于主要动作、当前选择和焦点；成功/警告/错误使用独立语义 token 并配文字或图标。具体色值在真实组件与两主题对比测试后冻结，不在本文声称已通过视觉验收。

沿用 Flutter 的组件主题和原生可访问语义，不新增 Web UI 依赖。一套清晰中文系统无衬线字体，字号尊重系统缩放；数字优先等宽字形以利核对，编号保留完整可复制文本。列表和表格依靠对齐、分组与适量分隔组织，避免用巨大卡片、营销横幅、玻璃模糊或装饰渐变挤占数据。

作为实现验收目标：普通文本对比度至少4.5:1，大字号至少3:1；焦点、控件边界及状态标识可辨，不只用颜色表达。触控目标至少48逻辑像素；桌面键盘可完成筛选、选择、表单与确认，焦点顺序符合阅读顺序，弹层关闭返回触发控件，Escape 不无提示丢弃草稿。屏幕阅读器读取表头、排序、选择数量、字段标签/错误、当前步骤及结果；进度只在有意义变化时播报。

所有交互提供正常、悬停（适用设备）、焦点、按下、禁用、忙碌和错误状态。移动端无仅悬停可达的动作。动效只用于状态变化，短促且尊重减少动画；无自动入场编排。加载保留布局，不阻断已有可读结果。200%文字缩放下主要操作和错误仍可访问，不用固定高度裁切内容。

## 10. 冻结交接与验收清单

开始 UI 编码前由集成负责人核对以下服务交付；不把本文当成接口已经冻结的证明。

1. **T4 RecordService：** 四实体查询身份与写命令 DTO、字段错误、预期 heads/版本、纠错/复制/历史转标准/删除恢复/合并/冲突结果；唯一修订提交与已提交回执语义。
2. **T6 QueryRepository：** 组合过滤、稳定游标与关系批量读取、精确比较分组、排除理由、最新同日并列；需要刷新时的版本语义。
3. **T5 BackupService / 任务与文件端口：** 候选验证/激活令牌、只读能力、任务观察/取消/重试、文件发布完成层级和结构化错误；UI 不拥有事务与写锁。
4. **T7/T9 ExchangeService：** 行三态操作、候选匹配、双回执及确认事件生命周期、预览失效、提交结果游标、同步全包验证和恢复任务 DTO。

T8 验收覆盖标准必填、历史纠错及复制、日期精度、精确金额、组合分页/比价、Excel修改回流与重复确认、备份重开。T10 增加三端分支、同内容并行确认、删除/重定向修复、陈旧预览、提交取消竞争与响应丢失恢复。交互测试走正式服务，测试夹具不能作为生产 CRUD 后门。
