# AI Native 数据与 Agent 审查

基线：`origin/main` `1138e2c`；独立分支：`codex/codex-agent`。不包含 Claude 尚未提交的修改。

## 改进计划与边界

1. 审查对象、关系、查询、派生业务规则和 Agent 调用链，按可复现的行为缺陷排序。
2. 先补回归测试，锁定已有只读工具和确定性业务计算，再改进对话连续性、协议校验和资源边界。
3. 修复查询与工具输出中会造成误判的问题，保持 SQLite 为唯一事实来源，保持人工确认写入。
4. 运行核心测试、静态分析及受影响的 Flutter 测试，并进行独立复核。

不引入新依赖、业务服务器、图数据库、向量数据库或多 Agent 编排框架。借鉴 Palantir 的对象/关系/动作语义与 Codex、Claude Code 的受控执行循环，不复制其部署规模。模型沿用项目配置；本轮用确定性假模型验证运行时，不调用真实付费模型，也不读取历史密钥。

## 审查结果

### 结论

当前主线已经有可用的领域模型、精确业务计算、只读工具循环和规格解析流程，但还不能把“有聊天框、有 ontology.dart”当作成熟 AI-native 的证据。几个底层契约实际失效：声明精确却用浮点筛金额，声明可查却永远只能取前 50 条，显示历史却不能理解追问，保存证据 ID 却不保证证据存在。这些问题会让模型基于错误或不完整的数据给出看似可信的结论。

现有架构值得保留：Flutter + SQLite、本地数据、确定性的报价/预算/规格判定、人工确认写入，以及同一组工具供应用助手与 MCP 使用。`ontology.dart` 与字段、枚举、关系验证器之间已有一致性测试，这比单纯维护一份模型提示词可靠。改进应沿这些已有接口完成。

### 缺陷与处理

文件定位以仓库路径为准；问题描述针对上述基线，当前实现已修复所列项目。

| 优先级 | 问题与证据 | 本次处理 |
| --- | --- | --- |
| P1 | `record_query.dart` 把十进制转成 REAL：合法值 `999999999999.000001` 与 `999999999999.000002` 被当成相等。原筛选和排序结果都可能错。 | 复用 `ExactDecimal` 注册 SQLite 精确排序规则，比较值保持规范十进制文本；测试极值相邻微单位的筛选和排序。 |
| P1 | 同文件把 boolean 绑定为字符串 `true/false`，数据库 JSON 布尔值却是 1/0，已确认参数查询会漏查。 | 按字段类型验证并绑定布尔值，覆盖 eq/ne/in 与非法参数。 |
| P1 | `agent_tools.dart` 的 query/related 无翻页路径；预算、比价、选价、矩阵静默截断明细。 | 添加分页与完整性元数据；业务明细支持更小的 limit，汇总仍覆盖全部数据。分页增加版本检查，数据变化时要求重查，避免并发更新造成重复与遗漏。 |
| P1 | `assistant.dart` 只限制轮数，不限制每轮工具数量或上下文大小。畸形 tool call 直接强制转换，异常会穿透页面。 | 工具整批校验、调用预算、字符预算、总等待时限；超大结果明确返回可恢复错误，空回答/截断回复不再视为成功。 |
| P2 | `ask_page.dart` 保存历史但每次只发送当前问题；“这家供应商呢”丢失指代。损坏历史可抛 RangeError。 | 最多 6 轮完整成功问答、12,000 字符；旧答案仅作指代上下文，要求重新查询事实。页面严格校验历史结构。近期对话默认不发送，用户显式开启后才用于追问。 |
| P2 | 页面不能停止查询，失败统一显示“检查网络”，掩盖协议/预算错误。 | 增加停止按钮与离页取消；显示真实失败原因，阻止迟到回复继续执行工具或覆盖页面。 |
| P2 | `product_param.attachment_id` 只有 UUID 格式校验，`store.dart` 与 `exchange.dart` 漏掉附件存在性检查。 | 本地保存、交换与恢复检查证据附件，错误时事务回滚；空来源仍兼容。 |
| P2 | `data_quality.dart` 对每个已分类物料逐个读取参数，数据中心体检存在 N+1 查询。 | 批量读取参数代码并共享完整度纯函数，无新增缓存状态。300 物料测试中完整体检从 1,404 次 SELECT 降到 11 次。 |
| P2 | `quote_options` 对非法 qty 用 null 继续运行，用户以为考虑了数量，实际跳过起订量/费用分摊依据。 | 非法数量显式报错，让模型修正参数。 |

### 借鉴什么，以及如何保持轻量

| 来源 | 应采用的设计 | 在本项目中的落点 |
| --- | --- | --- |
| [Palantir Ontology](https://www.palantir.com/docs/foundry/ontology/overview/) | 对象、属性、关系承载业务语义。 | 保留稳定实体 ID、类型化字段和关系；SQLite 是事实来源，聊天摘要不是业务主数据。 |
| [Palantir Action types](https://www.palantir.com/docs/foundry/action-types/overview/) | 业务动作统一校验一次事务中的对象变更。 | 继续复用现有导入预览、采纳、预算等领域入口。未来若开放 AI 写入，只开放少数带预览/版本校验的业务动作，不给通用 SQL 写权限。该扩展未在本轮实现。 |
| [Palantir Action log](https://www.palantir.com/docs/foundry/action-types/action-log/) | 决策上下文与普通编辑历史分开。 | 保留模型建议、原文证据、人工确认与实际记录的区别。本轮修复附件引用；未把聊天记录伪装成完整决策审计。 |
| [OpenAI Running agents](https://developers.openai.com/api/docs/guides/agents/running-agents) | 模型、工具反馈、结束条件构成运行循环；会话状态策略要一致。 | 保持单 Agent 循环，补全协议与预算控制；只重放完整问答，不混入未完成工具序列。 |
| [Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/) | 运行时管理工具和上下文，而不是仅靠一段提示词。 | 把调用上限、结果大小和结束行为写进代码与回归用例；终轮只汇总已知证据。 |
| [Claude Code 的执行机制](https://code.claude.com/docs/en/how-claude-code-works) | 获取上下文、执行、验证；可中断；上下文是有限资源。 | 工具错误可反馈修正，业务计算交给现有确定性函数，用户可以停止；旧答案不直接当作当前报价。 |
| [Anthropic Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) | 从简单结构开始，效果证明有必要时再增加复杂度。 | 规格抽取继续走固定流程，跨对象探索使用有界 Agent；没有引入图数据库、向量库、多 Agent 编排或新依赖。 |

以上落地方式是结合项目的工程判断，不表示这些产品要求使用同样实现，也不表示需要迁移到某个云端 Agent SDK。

### 运行时约束

- 每次最多 8 轮工具推理，额外一次不提供工具的结果汇总；全程最多 24 个工具调用。
- 单问题最多 8,000 字符，历史最多 6 轮且合计 12,000 字符；单工具结果最多 16,000 字符，消息上下文最多 64,000 字符。这是确定性字符预算，不是精确 token 计费上限。
- 默认总等待上限 3 分钟。停止会结束本地等待并阻止后续步骤；已经发出的提供商请求可能继续完成并计费，未声称远端取消。
- 超大工具结果不会裁成看似完整的 JSON，而是返回明确错误；缩小 limit 或条件后重试。高维询价矩阵或特别大的单条记录仍可能超限。
- 工具仍为只读。未新增账户、授权体系、服务器、自动写入 Agent 或多 Agent 平台。

### 剩余限制与下一步

1. **回答可信度尚无端到端质量结论。** 假模型测试证明运行时契约，不能证明真实模型不会幻觉。下一步应以匿名化任务集分别评估实体命中、工具参数、证据覆盖、任务完成和不完整数据下的克制程度；单独的规格解析正确率不覆盖“问数据”能力。
2. **自然语言中的记录引用尚未逐个做证据来源核验。** 点击能定位对象不等于结论成立；后续可优先为金额结论展示查询证据，而不是增加更多自主能力。
3. **数据中心仍同步扫描全库。** 本轮消除了参数 N+1，但重复检测、完整体检和较大矩阵仍需读取数据。更大规模应根据本机实测决定是否移到已有后台执行通道；未引入容易过期的隐式缓存。
4. **旧库可能已经有悬空参数证据。** 修复后这类交换会明确失败并回滚，需要补回附件或人工清空错误来源，不能悄悄丢掉证据字段。正常缺省/null 字段兼容。
5. **动态本体、自治写入和持久执行审计尚未实现。** 当前动作目录主要用于说明人工操作。若未来开放 AI 变更，应先做有限领域动作、预览、版本检查、幂等确认和结果核验；无需把整个 Palantir 平台搬进桌面应用。
