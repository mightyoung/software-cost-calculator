# AI任务跨重启恢复

## 实施前计划

1. 独立本机SQLite任务日志，保存已提交输入、状态与成功模型步骤；不保存API Key，不进入业务同步或备份。
2. 共享LLM核心按完整请求重放已完成步骤；请求、模型或提示变化时废弃其后的旧步骤，业务工具重新查询，最后仍走领域校验。未取得响应的在途请求可能需要重发，不能保证提供商只计费一次。
3. 提供AI任务列表和主动继续入口，覆盖现有问答、智能导入、清单匹配和条款读取。启动只把中断任务标为可继续，不自动调用在线模型或写入业务数据。
4. 整库恢复开始前持久失效旧代际、取消AI并阻止新任务；晚响应不得保存或应用。确认写入使用业务事务内的本机回执，解决“已提交但任务状态没来得及更新”的重复操作窗口。
5. 回归包含关闭重开、进程强杀、重放复用、请求变化、取消/删除、重复确认、整库恢复失效及UI重新打开；单独审查后运行测试与静态分析。

## 已实现

侧栏新增「AI 任务」。问数据、智能导入报价、按清单建项目和条款解析均通过 `AppState.runAiTask` 与共享 `LlmClient` 保存检查点。退出页面或重启之后，在任务列表点击「继续」恢复；启动、打开任务列表均不会自动调用模型。

任务日志位于应用数据目录的 `ai-jobs.sqlite`，使用 SQLite WAL、FULL 同步、进程文件锁和会话所有者校验。已提交的原始文本、附件及成功模型响应保存在本机。API Key 不写入检查点；业务库备份、交换包不携带任务库或本机确认回执。没有引入 Redis、后台服务或新依赖。

恢复重跑领域流程，相同请求复用模型步骤。模型、服务地址、提示或工具查询结果改变时，丢弃不匹配位置及后续检查点。查询工具重新读取当前业务库，导入计划与领域校验重新执行；自动 compact 的上下文也从重放流程重新构建，不持久化陈旧查询上下文。无效 JSON、空回答和畸形工具调用会撤销相应检查点，避免恢复永远重放失败输出。

导入恢复停在核对页面，确认后才写入业务数据。条款恢复保留既有行为：解析结果保存为待核对条款，不自动确认或定选。条款原文、类别变化会拒绝旧任务；条件不再允许解析时明确提示。问答恢复重新读取业务证据，已变更查询结果触发后续模型请求重新生成。

确认操作把业务变化和不透明的任务回执放进同一个数据库事务。若业务提交后、任务状态更新前崩溃，重新打开任务列表会协调为已完成，重复确认被拒绝。整库恢复开始前先持久化失效旧任务代际、取消在途请求并阻止新任务；恢复失败也不复用已失效的旧任务。

- 核心完整测试 268 项通过；在线测试默认跳过，在已授权环境单独运行通过。核心与 Flutter 静态分析无问题，`git diff --check` 通过。
- 核心回归包含关闭重开、真实子进程 SIGKILL 后 WAL 恢复、独占所有者、删除/取消/整库恢复后迟到写入、请求变化后的后缀失效、无效输出后重新生成，以及凭证和业务交换隔离。
- Flutter 恢复测试覆盖导入草稿恢复不增加模型调用或业务写入、改输入创建新任务、任务中心显式继续、问答重放时重新读取已改变数据、条款输入变化拒绝旧结果、回执事务回滚和重复确认、业务已提交但日志仍待确认的重启协调，以及关闭后没有迟到通知异常。

- DeepSeek 在线实测 1 项通过：真实调用后关闭重开任务库，恢复结果相同；重放时使用会直接抛错的 transport，证明确实没有第二次网络请求。密钥仅从已授权 `.env` 装入测试进程环境。
- 独立审查发现的“失败输出永久缓存”与“条款恢复入口静默无操作”均已修复，并增加相关回归。

## 使用边界

- 保存的是已提交输入及成功模型步骤。核对表单里尚未确认的手工修改没有单独自动保存；继续会从原始输入和模型步骤重新生成核对草稿。
- 崩溃时仍在途、尚未收到并保存的响应需要重发；无法保证提供商不重复计费。用户取消后重启不会自动重发。
- 本机任务日志独立于业务备份，不提供跨设备迁移；删除任务不删除已经导入的业务数据。操作系统本身丢盘、任务库损坏不在正常重启恢复保证内。
- 新建任务时把已完成记录清理到最近 50 个，最多 100 个未完成任务；达到未完成上限时明确提示继续或删除旧任务，不静默清除用户工作。单份提交输入最多 32 MiB，检查点沿用核心单步容量边界。
- 参数提取的核心调用支持同一检查点接口，但项目目前没有独立参数提取页面，因此任务中心没有虚构这类恢复入口。
- macOS 本机已验证。Windows/Android 的文件锁与真实系统进程终止恢复尚未实机验证。
