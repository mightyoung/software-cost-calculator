# DeepSeek 在线验证

基线：`codex/codex-agent` / `73629f8`。用户明确授权使用本地 `.env` 的 DeepSeek API 密钥完成真实模型测试。

## 范围和方式

- 使用现有 `LlmClient`、`deepseek-flash` 与 `https://api.deepseek.com`，仅发送临时合成 SQLite 数据和测试需求，不发送实际业务库。
- 密钥仅由启动进程读取并放入子进程环境，不写入命令参数、版本控制或报告。在线脚本通过 `DEEPSEEK_API_KEY` 读取。
- 运行现有清单解析冒烟、20 道业务问答、标注条款解析，并新增本轮证据与引用路径的真实模型验证。
- 保留原始回答供逐项人工复核；自动数值/关键词/轨迹检查只是筛选，不能替代语义判断。小样本单轮结果不能代表生产准确率。
- 每次 Agent 问答沿用现有 3 分钟、8 轮工具、24 次调用预算。在线调用使用账户额度；没有创建新的云端服务或部署。

## 实测发现与最小修复

1. 表格里的 `UUID\|名称` 引用绕过原来的严格标记识别。已在 core 来源核验之前兼容单反斜杠分隔符；查过、未查过、备注注入均补先红后绿回归；公共引用格式仍严格，双反斜杠不宽松接受。
2. 系统提示原来包含缩略 UUID 示例，真实回答也出现 `supplier:f9…`。移除该示例并要求工具返回的完整编号，同时明确物料记录数不是库存数量。提示改动不构成幻觉消除保证。
3. 老 `ai_eval` 只做字符串包含，甚至可能从 UUID 命中计数。输出已明确改名“关键词命中”，任意失配退出非零；新增带证据的在线测试独立检查实际工具结果，再复核答案。
4. 条款评测原来低分仍正常退出、未检查标注数量。已增加条款数一致性检查和 `正确率≥90%、静默错误=0` 的退出门槛。

## 20 道答案复核边界

所有主问事实正确：供应商/报价数量、联系方式、物料查找、定标价、附加费、报价失效与起订量、项目选价、成本 49950、毛利 7492.5、15% 加价率、合同比较、询价回复、历史均价、预算预警和空预算。

仍然存在的附带问题：

- 第 19 题乙方有效价为 12800，但附带历史偏离沿用裸价 11800 的约 7.94%；有效价口径应约 17.07%。主问“甲方有效价最低”的结论正确。
- 第 14 题“最低”只在该询价单已回复报价范围内成立，不是全项目最低。第 9 题“未触发阈值，因此无需核实”是过度推论。
- 第 10 题称“两处提示”却列三处；第 11 题措辞容易暗示可执行写入。
- 第 3、13、18 题有表格转义引用；第 7 题有缩略伪引用；第 4 题部分引用降级未核验；第 6 题含无关裸 UUID。
- 第 20 题声称做了三种查询，但旧日志未保存轨迹，无法认证该过程主张。新在线评测保留轨迹。

因此，主事实检查通过与整段回答完全正确必须分开报告。以上剩余语义风险不能靠增加关键词规则掩盖。

## 条款解析不匹配的归因

[条款原始结果](../verification/2026-09-29-deepseek-spec_ai_eval.json) 保留三条不匹配：

- DP 接口采集、以太网转发：标注集合为空，AI 识别出两个端口条件。它是标注口径与推断许可的冲突，不能直接算“模型胡编”；当前校验也没有证明上下行方向绑定，因此本轮不通过改 golden 来提高分数。
- `OPC DA/UA`：现有枚举匹配只认完整 `OPC UA`，共享前缀形式不匹配；AI 证据校验使用相同路径，且同属性去重拒绝集合补充。这是现有保守规则限制，不应归因于模型本身。后续可增加严格限定协议上下文的共享前缀解析，并补裸 UA 不误识别回归。
- 显示器 `2K` 未结构化：此次仍保留为不匹配；未在本轮改变分辨率语义和标注。

三个问题都被提示而非静默接受。69 条只是现有小型标注样本，不足以认证任意真实采购文档；也不能据此认定引入 AI 优于规则。

- [7 项 Agent 在线结果](../verification/2026-09-29-deepseek-live.json)：真实 DeepSeek 调用，自动检查 7/7，退出码 0；每题保留问题、回答、结构化工具参数与结果、轮数、耗时和警告。该 JSON 明确 `live_model_evaluated=true`、`manual_review_required=true`。
- 覆盖精确 `999999999999.999999` 金额及引用、3 条预算只取 1 条明细而总成本仍为 6、已确认参数计数 1、忽略备注指令且仅引用已查对象、空查询、缺失项目不能臆测成本，以及拒绝删除并验证全部表内容未变。
- 评分器允许合理的额外 `describe/search/get`，不要求模型照抄预设调用序列；数字检查剥离 UUID 并检查完整数值，预算题禁止额外读取明细。自动通过仍不等于整段语义正确。

独立逐题复核：7/7 主问事实正确，10 处结构化引用均能追溯到本题成功返回的对象；不存在阻断性自动虚报。仍有三处附带越界：空查询回答声称连已删除／合并记录也覆盖，但搜索索引排除这些对象；缺失项目的“或已删除”推测不成立，因为 `get` 包含软删除对象；只读回答引入“有权限的同事”，而本应用没有该权限机制。它们不能被自动 7/7 掩盖，仍需后续约束与更大样本评测。

decimal、empty 答案在解释忽略备注时复述了注入标记，轨迹及答案没有执行该指令。是否允许解释时引用恶意原文，与是否执行它是两个不同的判定。

最终无网验证：核心完整测试 235 项、问数据页面 12 项通过；核心静态分析与 diff 检查通过。无新依赖、数据库迁移、服务或 UI 扩展。
