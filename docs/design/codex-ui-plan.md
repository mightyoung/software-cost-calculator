# UI 改版执行边界

基线：2026-09-29 拉取的 origin/main（1138e2c），独立工作树和 `codex-ui` 分支。Claude 的工作树不参与本次编辑。

## 目标与判断

现状的问题是业务层级弱、桌面导航视觉重量过高、移动端标题和操作识别不足。采用 Operate 模式：浅色工作区、克制的蓝色交互、清晰标题、可扫描的表格和任务队列。保留中文、系统字体、精确金额、导入确认、快捷键、数据交换及所有业务能力。

## 执行顺序

1. 运行既有行为测试作为基线；读取现行截图并独立评审。
2. 更新共享主题、导航、表格焦点及移动端触控反馈。
3. 重排工作台与项目列表，修复项目选中反馈；预算摘要和页签按空间适配。
4. 补充窄屏、短窗口、放大文字与键盘操作回归；运行应用测试和静态检查。
5. 批量生成桌面、手机和深色截图，统一修复后至多再确认一轮；独立审阅。

## 验收与证据边界

- 数字、税制、单位、告警和待确认状态必须仍然可见，不修改核心计算或数据库。
- 手机保留底部导航和明确的操作名称；桌面保留高效的表格与键盘路径。
- 测试渲染不是 Windows / Android 真机认证。截图使用测试示例数据。
- Canva 方向板仅供沟通，实际 Flutter 渲染为交付依据。
