# 第二版 UI 方向：四个参考如何用于询价与预算系统

日期：2026-09-29。分支：`codex-ui`。状态：设计研究与交互示意，尚未替换 Flutter 生产界面。

## 判断

可以借鉴，而且比上一版方向更适合。建议以 **Dify 的亮色层次、Grok 的暗色层次、Claude 的排版节奏、Codex 的工作区结构** 形成同一套业务界面。不能把四个产品的控件各抄一部分；颜色、字体、间距和交互状态仍须统一。

上一版更像把默认管理后台整理了一遍，缺少鲜明且一致的视觉判断。问题不只是配色：导航、项目列表、数据和详情同时争抢空间；标题、标签、状态的分量接近；中文与数字没有形成稳定的阅读节奏。继续加圆角、边框和卡片不会解决这些问题。

## 参考证据及适用边界

| 参考 | 实际核验 | 值得采用 | 不宜照搬 |
| --- | --- | --- | --- |
| Dify | 官方仓库固定提交的亮色 token | 冷灰页面、白色工作面、少量明确的蓝色操作 | 工作流画布、遍布强调色的状态 |
| Grok | 当前公开产品 CSS 的最终 dark override | 微暖近黑的三级表面，浅色主要操作 | 对话首页的大面积留白、弱化业务告警 |
| Claude | 官方网站 CSS、字体文件字符覆盖；官方外观设置文档 | 常规字重、舒适行高、正文与工具文本的层次 | 官网大号衬线标题；未经授权打包专有字体 |
| Codex | 本机宿主 26.924.22138 的静态布局样式及官方介绍 | 可收起侧栏、稳定主工作区、按需详情面板 | 将采购流程改成聊天、永久多列挤压表格 |

Dify 核验来源是仓库 main 的固定快照，不代表在线服务已部署完全相同版本。[亮色主题源码](https://github.com/langgenius/dify/blob/a4f949f173718974b0379dd0db8cf4401efaf8f8/packages/dify-ui/src/themes/light.css)

Grok 的最终样式覆盖使用 `hsl(30 5% 7%)`、`hsl(30 5% 9%)`、`hsl(30 5% 12%)` 等微暖黑。已核对公开 CSS；未完成登录后页面的视觉核验。[产品页](https://grok.com/) · [本次核验的 CSS](https://cdn.grok.com/_next/static/chunks/2u4u73gifhews.css)

Claude 官网使用 Anthropic Sans / Serif / Mono。实际检查的 Sans、Serif 文件均不覆盖中文 U+4E00–9FFF，因此写一个 Claude 字体名不能改善中文。`claude.ai` 本次受地区访问限制，不能把官网字体结论冒充为登录后应用事实。[官网](https://claude.com/) · [官网 CSS](https://claude.com/_next/static/chunks/a225f3c51dd248c1.css) · [官方外观设置](https://support.claude.com/en/articles/8887527-customizing-your-appearance-settings)

Codex 本机样式包含可调整侧栏宽度，默认 275px、最小 240px；这是参考产品的值，本系统建议缩至 224–248px，把空间交给表格。本机安装版本不等于已证明全球最新版本。[官方工作区介绍](https://openai.com/index/codex-for-almost-everything/)

## 配色：降低装饰，把颜色留给操作与异常

| 角色 | 亮色建议 | 暗色建议 |
| --- | --- | --- |
| 页面底色 | `#F2F4F7` | `#131211` |
| 主工作面 | `#FFFFFF` | `#181716` |
| 次级区域 | `#F9FAFB` | `#201F1D` |
| 正文 | `#101828` | `#EEEDEA` |
| 次级文字 | `#475467` | `#C6C4BF` |
| 主操作 | `#0033FF` / 白字 | `#EEEDEA` / 深字 |

以上是本项目建议值，不是四家产品完整设计系统的复刻。蓝色用于主操作、链接或选择；金额保持正文对比度。失效、超预算、待询价同时使用文字与语义颜色，不依赖颜色独自传达。暗色不用蓝黑覆盖整个工作区，也不把每张卡片都描亮边。

## 字体：先修正证据，再调整观感

发现上一轮 `apps/supplier_app/test/screenshot_test.dart` 把 Arial Unicode 的同一份字体数据注册为 Roboto 和多个中文 fallback 名称。截图中的中文字形因此不能代表生产环境的 PingFang、微软雅黑等字体。这是上一轮字体判断的证据缺陷。

建议生产 UI 与截图测试使用相同的、许可明确的中文无衬线字体及真实 400 / 500 / 600 字重。跨平台一致性优先时，可以评估随应用打包 Noto Sans CJK SC；不能仅在 fallback 列表写名称，也不能擅自从 Claude 网站下载字体随应用分发。[Noto 使用与许可](https://notofonts.github.io/noto-docs/website/use/) · [Flutter 自定义字体](https://docs.flutter.dev/cookbook/design/fonts) · [字体回退](https://api.flutter.dev/flutter/painting/TextStyle/fontFamilyFallback.html)

建议规格：正文 14px/1.5–1.6，表格 13–14px，重要辅助信息至少 12px，页标题 22–24px/600，分区与行名称 500，常规内容 400。金额右对齐、等宽数字，避免整页代码字体。衬线只在长篇说明或报告阅读场景评估，不用于报价表。桌面与移动端均需支持系统文字缩放。

研究稿暂用本机系统字体，尚未新增字体资产，因此不能据它宣称 Windows、Android 字形已经统一。

## 布局：按业务映射 Codex 的空间分配

| 业务场景 | 中央工作区 | 按需右侧面板 | 应保留的业务重点 |
| --- | --- | --- | --- |
| 项目预算 | 费用分类、预算明细、合计 | 选中物料的供应商与选价依据 | 数量×单价、费用口径、缺价与失效 |
| 报价库 | 搜索、筛选、报价列表 | 规格、历史报价、附件 | 全局资料与项目采用记录分开 |
| 询价比价 | 供应商对比矩阵 | 单个报价的原文与差异 | 同税制、币种、数量门槛后再比较 |
| 导入审阅 | 差异预览、错误与冲突 | 选中行的原始来源 | 确认范围、预览版本、处理结果 |
| 备份与交换 | 分组任务页、进度和结果 | 必要时查看日志详情 | 恢复阻塞与错误状态必须清楚 |

左侧只保留一层应用导航和最近项目，完整项目列表进入中央。中央是表格或任务页面；右侧是当前选择的依据，不再长期保留一列项目列表、一列导航、一列详情共同夹住表格。

桌面宽屏可显示三部分；中等窗口默认两部分，详情按需覆盖；手机采用单页列表与独立详情。断点应由中文字段、缩放后的可读宽度驱动，不能只检测操作系统。研究稿以 1160px 和 760px 演示，不是已定稿的生产断点。

页面保持一个明确主操作：预算页“添加费用”、报价页“录入报价”、询价页“发起询价”、导入页“确认导入”。导航收起、查看依据和行距属于次级操作。研究稿的蓝色“查看报价依据”是为了展示交互的临时入口，生产时应降为次级按钮。

表格保留可比列、固定表头和水平滚动；手机摘要不能吞掉数量、供应商或税制，省略字段必须能在详情找到。键盘焦点、返回关闭详情、恢复选中行和滚动位置都属于后续 Flutter 实施要求。

## 必须同时修正的业务表达

示例中成本 186,820、合同金额 205,000、对外报价 214,843。“报价减成本”是 28,023；“合同减成本”是 18,180。把前者笼统称为预计毛利，容易与实际合同收益混淆。建议明确显示计算口径及缺价项；这只是标签与解释的改进，不能擅自改变计算公式。

材料费 158,920 与成本合计差 27,900，应通过费用分类说明。报价列表必须允许同一物料多条供应商报价，不能直接把预算表改列名冒充报价库。历史失效价格可以作为预算快照存在，但应明确它需要复核；未报价项目不能被展示为零价的完整预算。

## 研究稿与落地次序

[打开交互研究稿](reference-study.html)：亮暗切换、项目切换、预算/报价、搜索、物料详情、收起导航和调整行距。全部为示例，不连接数据库；仅覆盖两个局部业务视图，未实现保存、导入、导出或全部移动交互。

实施建议按顺序进行：

1. 统一生产字体、真实字重及截图字体加载，保留现有业务回归测试。
2. 重建语义色与基础组件，消除页面内硬编码颜色；验证亮暗、焦点与禁用状态。
3. 改造壳层和项目预算页，先解决主工作区宽度与毛利口径标签。
4. 将相同结构应用于报价、询价、导入和备份任务；保留既有版本绑定、锁和恢复行为。
5. 完成 Windows / Android 原生检查、文字缩放、键盘/触摸及长数据表验收。网页样稿不能替代这些验证。

这轮产物是方向分析与可操作样稿；Flutter 生产代码仍为上一版，尚不能声称整套 UI 已按新方向完成。

## 本轮验证

浏览器实测 1440px 桌面与 389px 窄屏，页面没有整体水平溢出；查看了亮色桌面、暗色桌面和亮色窄屏。验证了主题切换、预算/报价切换、无搜索结果、空项目禁用详情、报价选择与关闭面板。修正了手机数量/单价不可见，以及两家报价同时被选中的问题；点击乙机电后仅一行选中，并显示正在核对的供应商。窄屏暗色做了状态及溢出检查，未单独进行截图评审。

独立审阅覆盖分析稿与原型，修复上述两项实质问题。本轮没有修改生产 Dart，也没有把网页检查算作 Flutter 或原生设备验证。
