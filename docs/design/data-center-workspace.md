# 数据中心专项改造

## 本轮实施结果

- 数据质量已提供待处理／全部切换、准确计数单位、问题对应操作和对象定义入口。参数操作保留预览流程，其余入口明确打开完整列表；不暗示已自动过滤或修复。
- 检查结果在应用数据变化时刷新，单纯筛选不重复执行检查。没有修改质量规则和数据库写入语义。
- AI 接入已支持工具搜索、无结果状态、窄屏纵排、配置与规则折叠，并按实际可执行文件存在状态展示 MCP 接入。
- 三个页面共享中性明暗配色。质量导航暴露的手机目录溢出已修复：工具栏换行，数据表局部横向滚动，保持纵向惰性构建、排序和批选。
- 参照 Palantir 的对象浏览结构完成 [G6 离线前端](g6/README.md)：分组目录、关系画布、关系／属性检查面板现已接入正式 Flutter 数据中心，真实计数和选择经宿主同步。基础视图保留为手动切换及失败回退，原生设备验证状态见[集成记录](frontend-integration.md)。
- 最新数据中心及截图测试 20 项、目录相关测试 13 项通过；覆盖 390px／1.4 倍文字、导航、搜索、筛选、业务数据无隐式改写。原生设备和实际大库性能仍待验证。

## 范围与实施顺序

在已完成关系图基础上，继续数据质量与 AI 接入；先以测试锁定核心检查和工具列表，再改界面与导航，最后检验桌面/手机放大文字和数据无副作用。保持 ontology、dataQuality、agentTools 为唯一业务来源，不新增修复规则或自动写入。

## 已发现的问题

1. 数据质量把已通过和待处理检查平铺，数字没有单位；重复项的统计实际是组，参数项统计是物料，不能加总成“受影响记录”。
2. 修复路径只是文字；用户看完还要自己找页面。三个参数操作与发现的问题没有关联，容易误以为点击就批量修复。
3. AI 接入把介绍、配置、工具长表和规则全部平铺，开发版本未包含可执行文件时文案却承诺正式包必然可用。
4. 工具名固定占150px，手机与放大字体下正文被挤压。深色关系图已中性化，但外围页签、质量页和接入页仍是蓝黑，视觉割裂。

## 设计方案

- 数据质量：默认待处理，允许查看全部；标明检查项数量与每条计数单位，保留核心排序。问题直接链接到对应模块或参数预览。明确打开完整列表，不假装已经过滤到问题记录。
- 模型衔接：可从质量条目进入对应对象的字段定义，选中同一 ontology 类型。
- AI接入：先说明只读能力与数据说明导出；工具可搜索并在窄屏纵排；技术配置与规则折叠，按实际文件存在状态说明可用性。
- 视觉与交互：三个页签共享中性明暗工作面，避免重复卡片嵌套。沿用全局减少动效策略，检查数据不随筛选或悬停重复查询。
- 验证：质量与AI基线、导航目的地、计数语义、检查筛选、工具无结果、手机放大字体、数据未被隐式改写。真实大库的质量检查耗时另需profiling，不能把界面缓存等同数据库性能优化。
